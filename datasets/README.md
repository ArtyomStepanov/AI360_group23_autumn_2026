# Датасеты

Датасет для текущих `fit` и `evaluate` должен наследовать
`torch.utils.data.Dataset`, реализовывать `__len__` и `__getitem__` и возвращать
пару тензоров `(x, y)` для одного примера. Используется Dataset с доступом по
индексу; IterableDataset текущими циклами не поддерживается.

## Формат одного примера

| Задача | `x` | `y` |
| --- | --- | --- |
| Изображения для CNN/DNN/ShallowNN | float32, `(3, 32, 32)` | Для CrossEntropyLoss: скаляр long, индекс класса |
| Бинарная классификация с одним logit | Формат входа выбранной модели | Для BCEWithLogitsLoss: float32, скаляр либо `(1,)` |
| Другие задачи | Формат входа выбранной модели | Форма и тип, совместимые с criterion и метриками |

Для C классов индексы многоклассовых меток должны лежать в `[0, C - 1]`.
Все части датасета должны использовать одинаковое соответствие классов и
индексов. Метки для BinaryAccuracy должны содержать только 0 и 1.

Не добавляйте батчевую ось в `__getitem__`: DataLoader добавит её сам. Например,
изображения `(3, 32, 32)` превращаются в `(N, 3, 32, 32)`, а скалярные метки —
в `(N,)`. Для BCEWithLogitsLoss формы выхода модели и меток должны совпадать.
Словари, вложенные структуры и строки вместо x/y потребуют изменений циклов:
сейчас к каждому из двух элементов применяется `.to(device)`.

## Пример

```python
import torch
from torch.utils.data import Dataset


class ImageDataset(Dataset):
    def __init__(self, images, labels, transform=None):
        if len(images) != len(labels):
            raise ValueError("Число изображений и меток должно совпадать")
        self.images = images  # CPU-тензор float32: (N, 3, 32, 32)
        self.labels = labels  # CPU-тензор long: (N,)
        self.transform = transform

    def __len__(self):
        return len(self.labels)

    def __getitem__(self, index):
        image = self.images[index]
        if self.transform is not None:
            image = self.transform(image.clone())
        return image, self.labels[index]


dataset = ImageDataset(
    torch.rand(8, 3, 32, 32),
    torch.randint(0, 10, (8,)),
)
```

Это пример интерфейса с синтетическими данными. Для файлового датасета храните
пути и метки, а чтение изображения и преобразование в тензор выполняйте в
`__getitem__`. Возвращайте CPU-тензоры: переносом на устройство занимается
цикл обучения или оценки.

## Подготовка данных

- Разделите данные на train, validation и test до обучения. Связанные примеры
  одного объекта не должны попадать в разные части, если это даёт утечку.
- Оценки нормализации и другие обучаемые преобразования рассчитывайте только
  по train, затем применяйте ко всем частям.
- Случайные аугментации используйте для train. Для validation/test задавайте
  фиксированные преобразования, чтобы оценки можно было сравнивать.
- Возвращайте примеры одинаковой формы, которые стандартный DataLoader сможет
  объединить в батч. Для разной длины или размера потребуется padding или
  собственный collate_fn, пока не передаваемый через fit/evaluate.
- Документируйте источник данных, разбиение, отображение классов, масштаб
  значений и преобразования. Для внешних наборов укажите способ получения.

## Ограничения циклов

`fit` перемешивает примеры и отбрасывает последний неполный батч. Сейчас
batch_size должен быть не меньше 2, а размер train — не меньше batch_size.
`evaluate` не перемешивает данные и учитывает все примеры, включая последний
одиночный батч; batch_size должен быть положительным, датасет — непустым.

Перед запуском проверьте длину датасета, форму и dtype одного примера,
формирование батча и согласованность с выходом модели, criterion и метриками.
Подробнее: [модели](../models/README.md) и [метрики](../metrics/README.md).
