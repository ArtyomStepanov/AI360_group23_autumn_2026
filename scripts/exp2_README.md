# Второй эксперимент: learning rate и размер батча

[exp2.py](exp2.py) проверяет гипотезу `lr_opt = k * batch_size` для C1 на CIFAR-10.
Полный перебор содержит **20 learning rate × 20 размеров батча = 400 моделей**.
Каждая модель обучается с нуля 10 эпох. Один seed, 67, фиксирует начальные веса,
разбиение данных и генераторы sharpness. Повторов с другими seeds в этой сетке нет.

## Сетка и условия

Сетка содержит степени двойки 64, 128, 256, 512, 1024, 2048 и промежуточные
значения, кратные 64 и 128, — всего 20 батчей:

```text
64, 128, 192, 256, 320, 384, 448, 512, 640, 768,
896, 1024, 1152, 1280, 1408, 1536, 1664, 1792, 1920, 2048
```

Learning rate — 20 значений, включающих соответствующий удвоению батча ряд
0.001, 0.002, 0.004, 0.008, 0.016, 0.032, промежуточные значения и запас
по краям диапазона:

```text
0.000125, 0.00025, 0.0005, 0.00075, 0.001, 0.0015, 0.002, 0.003, 0.004, 0.006,
0.008, 0.012, 0.016, 0.024, 0.032, 0.04, 0.048, 0.064, 0.096, 0.128
```

Эти значения позволяют проверить масштабирование от lr=0.001 при batch=64
и охватывают область лучших lr из тестового запуска. Полный перебор остаётся
декартовым произведением сеток: каждая модель обучается с одной независимой
парой (batch_size, lr). Зависимость оптимального lr определяется по результатам.

Используются C1, Adam с параметрами по умолчанию кроме lr, CrossEntropyLoss и
нормализация CIFAR-10 из exp1. Scheduler и warmup не используются; lr постоянен
в течение всех 10 эпох. На CUDA обучение использует AMP.

Из стандартной обучающей выборки выделяются 45 000 примеров для обучения и
5 000 для validation. Стандартная test-выборка из 10 000 примеров используется
для отчёта, но не для выбора оптимального lr. Разбиение одинаково для всех моделей.
Данные скачиваются в `datasets/`, если ещё отсутствуют.

В fit последний неполный батч отбрасывается. При фиксированных 10 эпохах
различаются число обновлений весов и число учтённых примеров. Результат относится
к этому протоколу обучения, а не к сравнению при одинаковом числе обновлений.

Sharpness считается на всей обучающей части, с одинаковыми epsilon=5e-4,
maxiter=10, subspace_dim=100 и seed=67. Для каждой модели выполняются три
запуска LBFGS из разных случайных начальных точек в одном подпространстве;
результат — максимум среди трёх оценок. Матрица A, границы и базовый loss общие
для всех стартов. AMP при этом выключен.
Батч оценки и sharpness по умолчанию равен 256 и не зависит от обучающего батча.

## Запуск

Из корня проекта в окружении с установленными requirements.txt:

```bash
python scripts/exp2.py
```

Проверить один полный прогон перед запуском всей сетки:

```bash
python scripts/exp2.py --limit 1
```

Повторный запуск без `--limit` продолжит ту же сетку до 400 моделей.
Количество эпох остаётся 10; `--limit` ограничивает только число новых прогонов.

Выбор устройства и числа процессов загрузки:

```bash
CUDA_VISIBLE_DEVICES=0 python scripts/exp2.py --workers 4
```

По умолчанию используется первая видимая CUDA GPU, иначе CPU. Один процесс
последовательно обучает модели на одной GPU; дополнительные GPU автоматически
не используются.

Диапазоны можно задать явно, сохраняя сетку из 400 моделей. При изменении
границ соответствующая сетка генерируется с логарифмическим шагом:

```bash
python scripts/exp2.py --max-batch 1024 --min-lr 1e-5 --max-lr 0.1 \
    --output-dir results/exp2_batch1024
```

Доступны `--min-batch`, `--max-batch`, `--min-lr`, `--max-lr`, `--seed`,
`--workers`, `--eval-batch-size`, `--sharpness-starts`, `--device`, `--output-dir`, `--limit` и
`--analyze-only`. Слишком узкий диапазон, не дающий 20 различных значений,
вызывает ошибку. При нехватке VRAM скрипт останавливается, сохраняя результаты;
он не меняет размеры батча и не заменяет обучение накоплением градиентов.

## Сохранение и возобновление

По умолчанию файлы находятся в `results/exp2/`:

| Файл | Содержание |
| --- | --- |
| config.json | Сетка, seed, размеры выборок и параметры оценки |
| checkpoints/batch_B_lr_II.pt | Полное состояние обученной модели и время обучения; II — индекс lr в config.json |
| results.csv | Одна строка на модель: batch_size, lr, seed, epochs, status, val_loss, val_accuracy, test_loss, test_accuracy, sharpness, train_seconds, eval_seconds |
| best_lr.csv | Лучший проверенный lr для каждого батча отдельно по трём критериям |
| linearity.json | Число прогонов, параметры аппроксимаций, R² и диагностика оптимумов |
| best_lr.png | Лучшие lr и две аппроксимации для каждого критерия |
| grid.png | Тепловые карты validation accuracy, validation loss и sharpness |

Состояние модели сохраняется после обучения, до оценок. При прерывании
обучения незавершённая модель обучается заново; при прерывании оценок веса
загружаются из checkpoint. Строки из results.csv пропускаются при перезапуске.
400 состояний C1 занимают примерно 2.8 ГБ без состояния оптимизатора.

Изменённая конфигурация, тип устройства (CPU/CUDA), версия PyTorch или исходный
код скрипта, модели, обучения и метрик требуют нового `--output-dir`, чтобы не
смешивать эксперименты. Хеш этих файлов сохраняется в config.json.
Для полного эксперимента отдельно от тестовых результатов можно использовать
`--output-dir results/exp2_full`.
Одновременная запись нескольких процессов в один каталог не поддерживается.

Перестроить отчёт по уже сохранённым данным:

```bash
python scripts/exp2.py --analyze-only
```

Отчёт строится и после частичного запуска. В linearity.json указано, сколько
из 400 моделей записано, сколько имеет конечные значения метрик и какие батчи
полностью перебраны. Лучший lr выбирается только для батчей со всеми 20
завершёнными прогонами; тепловые карты показывают и частичные результаты.
Аппроксимации строятся начиная с трёх полностью перебранных батчей, до этого
fits записывается как null. Модели с
нечисловыми значениями получают status=nonfinite; конечные значения каждого
критерия рассматриваются отдельно. Например, ошибка sharpness не исключает
конечные validation loss и accuracy из выбора lr.
Результат с нечисловыми метриками не считается 400 успешными моделями.

## Как проверяется гипотеза

Для каждого батча отдельно выбираются максимум validation accuracy, минимум
validation loss и минимум train sharpness. Accuracy лежит в диапазоне [0, 1],
sharpness выражена в процентах. При равной accuracy предпочтение получает
меньший validation loss, затем меньший lr. Для остальных критериев при равенстве
выбирается меньший lr. Число равных оптимумов сохраняется в поле ties.

По однозначным оптимумам внутри диапазона строятся `lr = a * B + b` и
`lr = k * B`, с R² для каждой аппроксимации. Точки с равными оптимумами,
граничным lr или нечисловыми значениями критерия среди 20 моделей батча
в аппроксимацию не входят. Они остаются в таблице и на графике.
Для аппроксимации нужны минимум три подходящие точки; их батчи перечислены
в поле fit_batches. Для гипотезы пропорциональности релевантна вторая формула;
также сохраняются lr/B и наклон в координатах log(B), log(lr), ожидаемый около 1.
Для постоянного оптимального lr R² не определён и записывается как null.

Повторные старты не гарантируют ненулевую sharpness: причиной нуля могут быть
плоская область или ранняя остановка LBFGS. Число нулевых оценок отражается
в linearity.json. Число стартов одинаково для всех моделей; при необходимости
оно задаётся через --sharpness-starts.

Поле boundary отмечает выбор минимального или максимального lr сетки: истинный
оптимум может лежать за пределами диапазона. Лучший lr определяется только
среди проверенных значений. Отдельные критерии могут давать разные зависимости;
малая sharpness сама по себе не означает хорошее качество классификации.

Графики и аппроксимации показывают измеренные результаты, включая нелинейную
зависимость. Один seed позволяет исследовать тенденцию; он не даёт оценки
разброса результатов. Adam сохранён для сравнения с exp1; гипотеза линейного
масштабирования для этого протокола может не подтвердиться.
