# Третий эксперимент: траектории small и large batch

[exp3.py](exp3.py) сравнивает обучение с батчами **256 и 4096** по умолчанию.
В каждой из трёх пар запусков (seeds 43, 44, 45) модели стартуют с одинаковыми
весами. Обучение: **100 эпох, Adam, lr=0.001, float32 без AMP**.
Архитектура выбирается через `--setup C1|C2|C3|C4`. C1/C2 используют CIFAR-10,
C3/C4 — CIFAR-100. Без `--setup` используется прежняя `RegularizedCNN`
из `draft/oldcode.py` на CIFAR-10: две свёртки, BatchNorm и Dropout.
Нормализация для всех запусков: mean=std=(0.5, 0.5, 0.5).
Данные скачиваются в общий каталог `datasets/`.

Цель — сравнить расстояние параметров от инициализации и его стабилизацию
в ходе обучения. Sharpness не вычисляется. Выход расстояния на плато сам
по себе не доказывает нахождение минимума: дополнительно рассматриваются
train loss и нормы градиентов.

## Запуск

Из корня проекта с установленными зависимостями сначала проверьте одну эпоху
для каждого батча:

```bash
python scripts/exp3.py --setup C1 --smoke-test
```

Этот режим использует один seed и пишет результаты в `results/exp3_C1_smoke/`.
Он проверяет оба выбранных батча, сообщает время обучения/оценки
и пиковую выделенную память CUDA за эпоху. Это не вся зарезервированная память
процесса, которую показывает `nvidia-smi`.

Полный запуск отдельно:

```bash
python scripts/exp3.py --setup C1
```

Результаты — в `results/exp3_C1/`. Для C2, C3 и C4 замените значение `--setup`:
каждая архитектура получает свой каталог `results/exp3_<setup>/`, а проверка —
`results/exp3_<setup>_smoke/`. Без `--setup` каталог — `results/exp3_RegularizedCNN/`.
Размеры можно изменить через `--small-batch 265 --large-batch 1024`.
Они записываются в конфигурацию и подписи графиков.
Доступны `--device cuda:0`, `--workers 2`,
`--eval-batch-size 1000` и `--output-dir`. CUDA выбирается автоматически при
наличии. Обучающий батч и точность автоматически не уменьшаются при нехватке
памяти: это изменило бы условия эксперимента.

## Результаты и интерпретация

- `config.json`: параметры, размеры выборок и число обновлений.
- `run_<seed>_SB.json`, `run_<seed>_LB.json`: история, сохраняемая после каждой
  завершённой эпохи. Веса не сохраняются; возобновления обучения нет.
- `epochs.png`: расстояние от инициализации, средняя норма градиента батча,
  средний train loss, test loss/accuracy и число обновлений по эпохам.
- `steps.png`: расстояние, норма градиента и train loss по шагам, с EMA
  и логарифмической осью шагов.
- `summary.json`: средние конечные расстояния и отношение SB/LB.

Непустой каталог результатов не перезаписывается. Для повторного запуска
укажите новый `--output-dir`. При прерывании остаются истории завершённых эпох;
PNG создаются после завершения всех запусков.

Графики показывают среднее ± стандартное отклонение по запускам, а не
доверительный интервал. Accuracy измеряется на стандартной test-выборке,
не на отдельной validation-выборке.

`fit` использует `drop_last=True`: для 50 000 примеров и батчей 265/1024
получается **9400 обновлений SB и 2400 обновлений LB** за 50 эпох;
за эпоху обрабатываются 49 820 и 49 152 примера соответственно.
В исходном `oldcode.py` использовались батчи 256/5000 и последний неполный
батч не отбрасывался.
Это сравнение при одинаковом числе эпох, а не при одинаковом числе обновлений.

Расстояние учитывает параметры модели, включая параметры BatchNorm, но не её
running statistics. Логируются градиенты батча до обновления и расстояние после
обновления. Train loss по эпохам — среднее batch loss в ходе обучения, с активным
Dropout, а не оценка всей train-выборки для конечных весов эпохи. Средняя норма
градиентов батчей не равна норме градиента всей выборки.
